# Original depot floor: native Unity import candidate

## Scope and provenance

This candidate selects **AST-GEO-MOD-005**, the project's original 4 × 4 m concrete floor, from the private extras source library. Only three runtime LOD meshes and six required original/derived texture maps are copied into the game repository. Editable Blender sources, hidden kit-proof geometry, damp alternatives, references, unrelated private files and third-party licensed downloads are excluded.

The source provenance records original AI-assisted Blender geometry and deterministic project-generated texture pixels, without external photographs, stock textures, downloaded meshes, characters or logos. The side concrete maps are original shared project inputs from MOD-001. This is selected runtime implementation under the cross-repository workflow, not a transfer of the entire private library or a new open-source license. The selected asset's [provenance](DEPOT_FLOOR_PROVENANCE.md) and [packet receipt](DEPOT_FLOOR_PACKET.json) preserve exact source/export hashes.

No Mixamo mesh is represented by this integration. Survivors and infected remain placeholder capsules.

## Native import contract

No glTF package or editor/package upgrade is introduced. Three FBX files use Unity's built-in ModelImporter. Each must import as one mesh renderer with two material slots, preserved normals, primary tiled PBR UV0 and unique UV1, calculated Mikk tangents and no animation/collider. Expected triangles: LOD0 318, LOD1 142, LOD2 12. Expected Unity meter-space bounds: X 0..4, Y -0.2..0, Z 0..4, root scale one. These are acceptance assertions, not proof until native Unity tests pass.

Material slots are explicitly 0=original aged concrete top, 1=original worn concrete sides. The runtime assigns two serialized shared URP Lit Resources materials, which retain texture dependencies and the required normal/metallic shader keywords in player builds; they are not runtime-only Shader.Find variants. The Lit shader GUID was verified against the official Unity Graphics package source, and local import tests must confirm it resolves to the installed package shader. Top maps remain 2048² and side maps 1024². Base color is sRGB; normal maps are imported as NormalMap with the original OpenGL green convention, and metallic/smoothness maps are non-color. Packed-map R=0 (non-metal concrete), A=255 minus original roughness byte. No silent downsampling, rebaking or new texture content is intended. Original PBR coordinates intentionally repeat; unique lightmap coordinates are preserved separately and are not a claim of baked lighting.

`DepotFloorImport` applies only within the selected Resources/UndeadOvertime/DepotFloor directory. Its explicit menu is **Undead Overtime > Reimport original depot floor**. The current command also intentionally synchronizes and saves only the two required PBR shader flags on the two depot material assets after dependencies load; this semantic material update is part of the explicit setup scope. It imports the six textures, three runtime models and two material dependencies synchronously, then validates loaded assets and texture references before reporting completion. It does not intentionally change packages, project graphics settings, other importers or source art; native Unity may still serialize its generated project state, which must be recorded and preserved. Unity may serialize importer metadata for these newly added files; preserve and return any such new diffs for cloud review rather than editing or discarding them locally.

The first import gate uses uncompressed textures and mipmaps to verify fidelity. Full RGBA mip chains would be approximately 80 MiB across these six maps before platform-specific formats/overheads; this is a planning estimate, not a measured GPU allocation. Compression/budget optimization, lightmapping and target-hardware performance are separate gates.

## Arena integration and collision

Only the LAN range's rendered ground changes. An 8 × 8 grid repeats the original 4 m module over the existing 32 × 32 m arena. Three LODs per tile use proposed screen-height thresholds 0.25/0.08/0; the last LOD never distance-culls into a hole. The grid shares two materials, rather than creating per-tile materials. LOD transitions remain subject to visual review.

The original continuous 32 × 32 m ground BoxCollider remains the sole floor collision. Its renderer is hidden to prevent overlapping surfaces. Tile FBXs have no collider, so the visual sawcuts do not create player snags or network physics differences. Source joints recess up to 6 mm below the support plane; the intentional simple collider bridges them. No new obstacle, spawn, enemy navigation rule or network protocol is introduced.

Headless execution creates no floor meshes, renderers, materials or texture loads, and retains the same ground collider. Missing runtime files or malformed renderer/slot counts fail explicitly in rendered mode; they are not silently replaced by an alleged successful asset import.

## Native failure and importer-schema correction

The corrected Git storage candidate 8c56168 reached native Unity 6000.6.5f1. Compilation passed and all nine FBX/PNG bytes matched the packet receipt, but EditMode recorded **143 total / 132 passed / 11 failed**. The subsequent PlayMode run recorded **42 total / 34 passed / 8 failed**, all eight stopping on the unresolved floor PBR material; the headless floor test passed. No new player build, loopback run or visual acceptance followed.

Native import reported that the GUID-only metadata was interpreted as TextureImporter version 1 (minimum 10) and ModelImporter version 1 (minimum 25). Unity then expanded the nine metadata files. The corrected cloud metadata uses the actual native schema samples, TextureImporter 13 and ModelImporter 24600, preserves all GUIDs and explicitly records the static model/PBR texture contract, including animation type None. Recovered native model failures were caused by Legacy Animation components despite importAnimation=false. No external object remaps, platform-specific compression overrides or character rig mappings are introduced. Importer GetVersion advances to 2; static validation rejects GUID-only or structurally incomplete importer metadata. The import command checks metadata first and verifies material dependencies after synchronous import; a successful request alone is no longer labeled successful asset resolution.

Read-only native diagnostics further isolated the systematic texture failure: every PNG had a TextureImporter but returned null when loaded as Texture2D, and its generated metadata used textureShape 2 (cubemap). Both materials therefore had empty texture references in memory; the floor material also lacked its PBR keywords. The correction explicitly sets Texture2D shape 1 in metadata and preprocess code, with static and native regression assertions. `python Tools/test_importer_metadata_guard.py` verifies nine GUID-only and six cubemap fixtures are rejected, without writing project files. Source/native-generated metadata samples establish serialization layout, not automatically correct semantic defaults. A second native diagnostic confirmed all six main assets were UnityEngine.Cubemap, not Texture2D. Existing model assets loaded with expected bounds and submesh index counts, so no geometry/axis rebake is justified by these failures.

A separate native warning identified Unity's automatic LOD naming trigger in the standalone FBXs. The revision changes internal node/mesh names from _LOD0/1/2 to Detail0/1/2, while retaining the three public filenames and GUIDs. Offline binary comparison proves every Geometry child payload and Model transform payload is identical to the earlier exports: topology, normals, tangent data, UVs and material assignments are unchanged. All six textures are byte-identical. Native tests now reject nested importer-created LODGroups; each runtime tile must own the only group.

The failed run generated additional local metadata/material serialization changes. It also changed ProjectSettings.asset relative to the original protected baseline; the other eight protected files retained their bytes. Preserve and inspect that exact change rather than silently restoring, committing or calling the whole checkout unchanged. Applying this correction must reconcile only the reviewed generated floor metadata, with fresh hashes and explicit scope; unrelated local project settings and materials remain preserved.
